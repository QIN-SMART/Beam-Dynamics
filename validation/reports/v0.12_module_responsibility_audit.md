# v0.12 Module Responsibility Audit

Date: 2026-08-06 · 职责混叠检查（不改代码）

## 现状模块地图（实际文件 → 承担职责）

| 文件 | 当前职责 | 混叠判断 |
|---|---|---|
| shared/params.py | 配置解析 + 派生量(γ,β,p0) + lattice helper | 职责单一 ✓（但物理常数内嵌）|
| shared/output_schema.py | 输出 schema + JSON 写入 | 单一 ✓ |
| validation/backend.py | **配置读取 + lattice 构造 + AG 力组装 + OCELOT 追踪 + RF kick 公式 + 结果提取 + provenance** | ⚠️ **重度混叠**：backend adapter 与 physics equation 同处一个文件（run_ag 内联 solenoid/rf 公式、_ocelot_rf_kick 内联 kick 公式）|
| validation/beam_result.py | BeamResult 容器 + 度量 | 单一 ✓（内含 γ/β 派生，轻微）|
| validation/reference.py | 解析参考公式 | 单一 ✓（常数重复定义）|
| validation/common.py | 绘图 + 度量 + checkpoint 日志 | 绘图与日志混叠（轻微，可接受）|
| validation/test_*.py | 测试 + 部分承担模拟执行（run_beamline 调用）| 测试调用 backend ✓（test_gpt_route 直接 import 主路由跑 simulation——测试即集成入口，可接受）|
| GPT模拟/ued_beamline_v2.py | 主路由：config+lattice+beam+track+输出 | **生产路由单体**：全部职责在一个脚本（历史结构，v0.11 已分离 build_lattice_from_shared 便于测试）|
| AG/run_shared.py | AG 适配 + 输出 | 单一 ✓ |

## 关键混叠（已识别，本阶段不重构）

1. **backend.py = adapter + physics equation 混叠**（高优先）：solenoid k_s、RF kick 公式与 adapter 转换(p_oc=β0δ_p)同文件。风险：未来 SC 若在 backend 加公式，文件继续膨胀。**推荐**：未来拆 physics/ 模块时把公式抽走；本阶段只做边界文档化。
2. **ued_beamline_v2.py 单体**：主路由承担 config+lattice+beam+track+输出。v0.11 已把 build_lattice_from_shared 提为可测函数；完整拆分留待 GUI 阶段。
3. **test 同时承担 simulation 逻辑**：test_gpt_route_equivalence 直接调 run_beamline（这是集成测试的正确形态，非问题）；但 test_rf 的 controlled-set kick 测试在测试内重建 kick 输入（复制了 generate_parray 逻辑一小段）——可接受。
4. **plotting 与 result extraction**：common.plot_compare 只画图；save_results 写 JSON——职责已分 ✓。

## 结论
无必须立即重构的职责混叠；backend.py 的"adapter+physics"混叠与主路由单体是本阶段最大结构债务，**记录并留给 SC/GUI 阶段**，不擅自拆分（避免触碰已验证代码）。
